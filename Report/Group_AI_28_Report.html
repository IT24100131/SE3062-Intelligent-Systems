1. Introduction & Background Research

This project implements fundamental graph search algorithms and domain-specific heuristics on the UC Berkeley CS188 Pac-Man artificial intelligence framework. A classical search problem is formulated as an initial state s0, a successor function Succ(s) returning (next_state, action, step_cost), a goal test Goal(s) returning boolean, and an accumulated path cost g(n).

All four core search algorithms (DFS, BFS, UCS, and A*) share a unified Graph Search architectural skeleton. The distinguishing factor among these algorithms is the underlying fringe data structure and the queuing priority function:

Algorithm Fringe Data Structure Ordering / Priority Completeness Optimality Time / Space Complexity
DFS (Q1) Stack (LIFO) Deepest node first Yes (finite graphs with expanded set) No O(b^m) time, O(bm) space
BFS (Q2) Queue (FIFO) Shallowest node first Yes Yes (for unit step costs) O(b^d) time, O(b^d) space
UCS (Q3) PriorityQueue Path cost g(n) Yes (for positive step costs) Yes (arbitrary positive costs) O(b^(1 + floor(C*/eps)))
A* Search (Q4) PriorityQueue Evaluation f(n) = g(n) + h(n) Yes Yes (if h is admissible & consistent) Dependent on heuristic quality

Heuristic Properties in Graph Search: An admissible heuristic satisfies 0 ≤ h(n) ≤ h*(n), meaning it never overestimates the true cost to reach the nearest goal. In graph search with an expanded set, a stronger condition—consistency (monotonicity)—is strictly required: h(n) ≤ c(n, a, n') + h(n'). Consistency enforces the triangle inequality, guaranteeing that f(n) non-decreases along every path, preventing the need to reopen previously closed states.

    print("Start's successors:", problem.getSuccessors(problem.getStartState()))
    """

    # Q1 (Member 1): graph-search DFS. The fringe is a LIFO Stack, so the most
    # recently discovered node is expanded first (deepest-first).
    fringe = util.Stack()
    fringe.push((problem.getStartState(), []))
    expanded = set()
    while not fringe.isEmpty():
        state, path = fringe.pop()
        if problem.isGoalState(state):
            return path
        if state not in expanded:
            expanded.add(state)

                if successor not in expanded:
                    fringe.push((successor, path + [action]))
    return []

Logic & Data Structures (≤ 200 words):
DFS explores the deepest unexplored branches first by utilizing util.Stack (LIFO). The fringe stores tuples of (state, path). Graph search is implemented using an expanded set to track visited nodes. When a state is popped, the goal test is executed immediately; if true, the accumulated action list is returned. Otherwise, if the state has not been expanded, it is recorded in expanded, and each unvisited successor is pushed onto the stack with its updated action sequence path + [action]. Checking membership in expanded eliminates redundant loops and prevents infinite recursion on cyclic or infinite graphs. While complete on finite state spaces, DFS is non-optimal (expanding 146 nodes with path length 130 on mediumMaze, where the optimal path is 68).

BFS systematically examines search states in order of increasing depth by utilizing util.Queue (FIFO). Sharing the exact graph-search skeleton as DFS, each queue entry encapsulates (state, path). def uniformCostSearch(problem: SearchProblem):
    """Search the node of least total cost first."""
    "*** YOUR CODE HERE ***"
    # Q3 (Member 2): fringe is a PriorityQueue ordered by the accumulated path
    # cost g(n). A state is only finalised when it is popped (not when pushed),
    # which is what guarantees optimality with non-uniform step costs.
    fringe = util.PriorityQueue()
    fringe.push((problem.getStartState(), [], 0), 0)
    expanded = set()
    while not fringe.isEmpty():
        state, path, cost = fringe.pop()
        if problem.isGoalState(state):
            return path
        if state not in expanded:
            expanded.add(state)
            for successor, action, stepCost in problem.getSuccessors(state):
                if successor not in expanded:
                    newCost = cost + stepCost
                    fringe.push((successor, path + [action], newCost), newCost)
    return []

Logic & Data Structures (≤ 200 words):
UCS generalizes BFS to arbitrary non-negative edge costs. The fringe is implemented as a util.PriorityQueue storing (state, path, cost), ordered strictly by cumulative path cost g(n). Crucially, the goal test is conducted only when a state is popped from the priority queue, rather than upon successor generation; this ensures that any potentially cheaper path currently queued is evaluated first. When extracting a node, if it hasn't been expanded, it is committed to the expanded set and its successors are pushed with total cost g(s') = g(s) + stepCost. UCS is optimal for positive costs, correctly navigating exponential step-cost terrains such as StayWestSearchAgent and StayEastSearchAgent.

def aStarSearch(problem: SearchProblem, heuristic=nullHeuristic):
    """Search the node that has the lowest combined cost and heuristic first."""
    "*** YOUR CODE HERE ***"
    # Q4 (Member 2): same as UCS but the priority is f(n) = g(n) + h(n). With
    # nullHeuristic (h = 0) this degenerates to UCS; with an admissible and
    # consistent h it stays optimal while expanding fewer nodes.
    start = problem.getStartState()
    fringe = util.PriorityQueue()
    fringe.push((start, [], 0), heuristic(start, problem))
    expanded = set()
    while not fringe.isEmpty():
        state, path, cost = fringe.pop()
        if problem.isGoalState(state):
            return path
        if state not in expanded:
            expanded.add(state)
            for successor, action, stepCost in problem.getSuccessors(state):
                if successor not in expanded:
                    newCost = cost + stepCost
                    fringe.push((successor, path + [action], newCost),
                                newCost + heuristic(successor, problem))
    return []

Logic & Data Structures (≤ 200 words):
A* search guides exploration towards the goal using an evaluation function f(n) = g(n) + h(n), combining actual backward path cost g(n) with estimated forward cost h(n) via heuristic(state, problem). Using util.PriorityQueue, each element retains (state, path, cost) while its queue priority is assigned as g(n) + h(n). With nullHeuristic (h=0), A* behaves identically to UCS. When supplied with an admissible and consistent heuristic (e.g., Manhattan distance), A* guarantees finding the optimal path while significantly pruning the state space: on bigMaze, A* expands 549 nodes (optimal cost 210) compared to 620 nodes for unguided UCS.

class CornersProblem(search.SearchProblem):

            dx, dy = Actions.directionToVector(action)
            x, y = int(x + dx), int(y + dy)
            if self.walls[x][y]: return 999999

def cornersHeuristic(state: Any, problem: CornersProblem):
    """
    A heuristic for the CornersProblem that you defined.

      state:   The current search state
               (a data structure you chose in your search problem)

      problem: The CornersProblem instance for this layout.

    This function should always return a number that is a lower bound on the
    shortest path from the state to a goal of the problem; i.e.  it should be
    admissible (as well as consistent).
    """
    corners = problem.corners # These are the corner coordinates
    walls = problem.walls # These are the walls of the maze, as a Grid (game.py)

    "*** YOUR CODE HERE ***"
    # Q6 (Member 4): relax the problem by deleting the walls. The heuristic is
    # the cost of the cheapest tour (Manhattan distances) that starts at
    # Pacman and visits every unvisited corner. That is the exact optimum of
    # the relaxed problem, hence admissible; and it is consistent because a
    # single real step changes the relaxed optimum by at most 1.
    position, visited = state
    remaining = [c for c, v in zip(corners, visited) if not v]
    if not remaining:
        return 0

    def manhattan(a, b):
        return abs(a[0] - b[0]) + abs(a[1] - b[1])

    def cheapestTour(current, todo):
        if not todo:
            return 0
        return min(manhattan(current, c) + cheapestTour(c, [r for r in todo if r != c])
                   for c in todo)

    return cheapestTour(position, remaining)

Heuristic Design, Admissibility & Consistency Proof (≤ 200 words):
The heuristic solves an exact relaxed problem by removing maze walls and calculating the minimum Manhattan Travelling Salesperson (TSP) tour starting at Pac-Man and visiting all remaining unvisited corners. Since at most four corners exist, all permutation orders are evaluated recursively.
Admissibility: Removing walls relaxes transit constraints; actual maze distance between any two points is always ≥ Manhattan distance. Thus, the relaxed tour length never exceeds the true remaining cost (h(n) ≤ h*(n)).
Consistency: Moving one step changes Pac-Man's coordinates by 1, adjusting the relaxed tour cost by at most 1 (h(n) ≤ 1 + h(n')). It returns 0 when all corners are visited. On mediumCorners, A* expands only 741 nodes (far below the 1200 full-marks ceiling) with optimal cost 106.

    heuristic, there is a dictionary called problem.heuristicInfo that you can
    use. For example, if you only want to count the walls once and store that
    value, try: problem.heuristicInfo['wallCount'] = problem.walls.count()
    Subsequent calls to this heuristic can access
    problem.heuristicInfo['wallCount']
    """
    position, foodGrid = state
    "*** YOUR CODE HERE ***"
    # Q7 (Member 4): the true maze distance from Pacman to the farthest
    # remaining dot. Pacman must at least walk that far to eat that dot, so it
    # never overestimates (admissible). Maze distance obeys the triangle
    # inequality, so h(n) <= 1 + h(n') for any step (consistent). Distances
    # are memoised in problem.heuristicInfo so each BFS is run only once.
    food = foodGrid.asList()

        return 0
    cache = problem.heuristicInfo.setdefault('distCache', {})

    def dist(a, b):
        key = (a, b)
        if key not in cache:
            cache[key] = mazeDistance(a, b, problem.startingGameState)
        return cache[key]

    return max(dist(position, f) for f in food)

Heuristic Design, Admissibility & Consistency Proof (≤ 200 words):
h(state) is defined as the true maze distance from Pac-Man's current location to the single farthest remaining food pellet, computed via mazeDistance (exact shortest-path BFS respecting walls). To guarantee fast execution, all point-to-point maze distances are cached in problem.heuristicInfo['distCache'].
Admissibility: Because Pac-Man must consume every pellet, he must eventually reach the farthest dot; hence the true remaining cost is bounded below by the distance to that dot (h(n) ≤ h*(n)).
